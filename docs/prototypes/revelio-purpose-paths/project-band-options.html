Path tint, three ways of drawing it

Both things you spotted were bugs, not decisions. The lopsided borders were a specificity collision: the rule that draws the divider between bands carries two classes and only sets the top edge, so it was overriding the one-class rule on the marked bands and leaving a pale line on top against their own black line underneath. The empty strips were the card inheriting a 24 px row gap from the grid around it, which put a band of card background between every section — invisible while everything was white, obvious as soon as one band had colour.

Both are fixed in all three variants below. What changes between them is only how the tinted band is drawn: how its edges are ruled, and whether it spans the card or sits inside it.

Variant 1

Hard rules

2 px black on both edges, flush to the card. Drawn exactly like the unknown above it, so the two marked sections match.

The tint across all three paths

Whichever variant wins, the tint follows each path’s own colour, so the project band is never the same shade twice. All three sit within a point and a half of each other for contrast, so none reads louder than the others.
