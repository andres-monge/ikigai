## 1. System Overview

- **Core Purpose and Value Proposition:** An AI-powered web application to help users find their _ikigai_ (a reason for being). It provides three actionable career paths based on a user's profile, and upon selection of a path, generates a detailed, step-by-step action plan.     7. **Export:** The user can export their "Purpose Discovery" results or their final "Action Plan" to separate PDF documents.
- **System Architecture:**
    
    - **Frontend:** React SPA (Vite, TypeScript), using TanStack Query for server state. UI built with shadcn/ui and Tailwind CSS.
    - **Backend:** Node.js server (Express), acting as a Backend-for-Frontend (BFF).
    - **AI & Data:** Google Gemini (`models/gemini-2.5-flash-preview-05-20`). The search grounding feature is used for real-time salary data and educational resource lookups.
    - **Data Persistence:** For the MVP, session data is stored in-memory on the server (`MemStorage`). The schema is designed for a seamless transition to PostgreSQL.
    - **Deployment:** The application is packaged for deployment on Replit.

## 3. Feature Specification

### 3.1 Purpose Discovery & Refinement

- **User Story:** As a user, I want to answer a questionnaire and receive three personalized career paths. I then want the ability to chat with an AI assistant to adjust these paths before making my final choice.
- **Implementation Steps:**
    1. **Generation:** The initial flow remains as described in the previous spec: Questionnaire -> `POST /api/analyze` -> Gemini generates 3 paths -> Results page is displayed.
    2. **Refinement:**
        - The "Refine with Nami" button on the Results page opens the `ChatInterface` component.
        - A `context` prop will be passed: `<ChatInterface context="discovery" ... />`.
        - When the user sends a message, a `POST` request is sent to `/api/chat` including `{ sessionId, message, context: 'discovery' }`.
        - The server's chat handler will use this context to build a specific prompt for Gemini, including the user's questionnaire answers and the _current three purpose paths_, asking the AI to modify them based on the user's message.
        - The AI's response (which could be a revised set of paths in JSON format or just text) is streamed back via SSE. The client-side logic will parse this response and update the `purposePaths` in its state, causing the UI to re-render with the refined paths.

### 3.2 Action Plan Generation & Refinement

- **User Story:** As a user, after I've chosen my preferred career path, I want the system to generate a detailed, step-by-step action plan for me. I then want to be able to ask the AI for changes or clarifications to this plan.
- **Implementation Steps:**
    1. **Selection:** On the Results page, each of the three `PurposePath` cards will have a "Choose this Path & Get Plan" button. Clicking it calls `handleChoosePath(pathId)`.
    2. **Generation:**
        - This triggers a React Query mutation that sends a `POST` request to `/api/action-plan` with `{ sessionId, chosenPathId }`. A loading screen is shown.
        - The server receives the request and calls the Gemini Wrapper with a prompt focused on generating a detailed plan (milestones, skills, project ideas) for the _single_ chosen path. It will enable the search tool to find and cite YouTube course URLs.
        - The server saves the generated `actionPlan` object to storage and returns it.
        - The client navigates to a new `'actionPlan'` view, displaying the plan in a structured format (e.g., using Accordions).
    3. **Refinement:**
        - The Action Plan page will also have a "Refine with Nami" button.
        - This button opens the _same_ `ChatInterface` component, but with a different context: `<ChatInterface context="action_plan" ... />`.
        - The `POST` request to `/api/chat` will now include `{ context: 'action_plan' }`.
        - The server's chat handler sees this context and loads the _generated action plan_ into the Gemini prompt, allowing the user to have a focused conversation about refining it.

## 4. Database Schema

The normalized schema supports the distinct stages of the user journey.

### 4.1 Tables

- **`assessment_sessions`**: Stores the top-level session information.
    
    - `id`: `serial` (PK)
    - `session_id`: `text` (UNIQUE, NOT NULL)
    - `language`: `text` (NOT NULL, 'en' or 'es')
    - `responses`: `jsonb` (The initial questionnaire answers)
    - `core_drivers_analysis`: `jsonb`
    - `chosen_path_id`: `integer` (FK to `purpose_paths.id`, NULLABLE)
    - `action_plan`: `jsonb` (The detailed action plan)
    - `created_at`: `timestamptz` (DEFAULT `now()`)
    - `updated_at`: `timestamptz` (DEFAULT `now()`)
- **`purpose_paths`**: Stores the three (potentially refined) paths.
    
    - `id`: `serial` (PK)
    - `session_id`: `integer` (FK to `assessment_sessions.id` ON DELETE CASCADE)
    - `title`: `text` (NOT NULL)
    - `description`: `text`
    - `ikigai_alignment`: `jsonb`
    - `action_strategy`: `text` (High-level strategy)
- **`salary_data`**: Stores salary info linked to a specific path.
    
    - `id`: `serial` (PK)
    - `path_id`: `integer` (FK to `purpose_paths.id` ON DELETE CASCADE)
    - `entry_level`, `mid_level`, `senior_level`: `text`
    - `location`: `text`
    - `sources`: `text[]` (Array of strings)
    - `retrieved_at`: `timestamptz` (DEFAULT `now()`)
- **`chat_messages`**: Stores all chat history, regardless of context.
    
    - `id`: `serial` (PK)
    - `session_id`: `integer` (FK to `assessment_sessions.id` ON DELETE CASCADE)
    - `role`: `text` (NOT NULL)
    - `content`: `text` (NOT NULL)
    - `context`: `text` ('discovery' or 'action_plan')
    - `created_at`: `timestamptz` (DEFAULT `now()`)

## 5. Server Actions

### 5.1 API Endpoints

- **`POST /api/analyze`**: Orchestrates the initial Purpose Discovery.
- **`POST /api/action-plan`**: Orchestrates the detailed Action Plan generation for a single chosen path.
- **`POST /api/chat`**: Handles chat messages for refinement.
    - **Input:** `{ sessionId: string, message: string, context: 'discovery' | 'action_plan' }`
    - **Logic:** Uses the `context` field to load the correct data (either the 3 purpose paths or the single action plan) into the Gemini system prompt, ensuring the AI's response is relevant. The response is streamed back via Server-Sent Events (SSE).

### 5.2 Gemini Wrapper (`server/grounding.ts`)

- **Description:** A centralized module to handle all interactions with the Gemini API.
- **`generateWithRetry(prompt, options)`**:
    - **Logic:** Implements retry-on-failure with exponential backoff. Validates JSON responses against Zod schemas. Logs API usage for monitoring.
